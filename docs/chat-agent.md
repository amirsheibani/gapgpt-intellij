# ایجنت چت

چت GapGPT یک ایجنت برنامه‌نویسی است: خودش فایل‌های پروژه را می‌خواند و جستجو می‌کند، با تأیید شما فایل ویرایش می‌کند و دستور اجرا می‌کند.

مرتبط: [راهنمای شروع](getting-started.md) · [ارتباط با API گپ‌جی‌پی‌تی](gapgpt-api.md) · [قوانین و اسکیل‌ها](instructions-import.md) · [فهرست مستندات](README.md)

## ابزارها

| ابزار | کار | تأیید |
|---|---|---|
| `list_dir`، `glob`، `grep`، `read_file` | دیدن و جستجوی پروژه | لازم نیست |
| `find_symbol`، `file_outline`، `find_references`، `go_to_definition`، `file_relations` | پیمایش کد با index خود IDE (بخش بعد) | لازم نیست |
| `todo_write` | فهرست کارهای یک کار چندمرحله‌ای | لازم نیست |
| `edit_file`، `write_file` | ویرایش و ساخت فایل (با diff viewer خود IDE) | لازم است |
| `run_command` | اجرای build، تست، git و … | لازم است |
| `mcp__<server>__<tool>` | ابزارهای سرورهای MCP | لازم است، مگر ابزار `readOnlyHint` داشته باشد |
| `exit_plan_mode` | ارائهٔ طرح در حالت طرح | تأیید طرح |

همهٔ مسیرها به پوشهٔ پروژه محدودند. «همیشه اجازه» فقط تا بسته شدن IDE معتبر است.

## پیمایش کد (`CodeTools`)

این ابزارها همان کار گراف کد (graphify) را انجام می‌دهند، اما روی index و PSI خود IDE. پس همیشه به‌روزند، ابزار خارجی نمی‌خواهند و برای هر زبانی که IDE می‌شناسد کار می‌کنند.

| ابزار | پاسخ | پیاده‌سازی |
|---|---|---|
| `find_symbol(name)` | محل تعریف کلاس، تابع، فیلد و … با این نام. اول تطابق دقیق، بعد نام‌هایی که این متن را دارند | contributorهای Go to Class / Go to Symbol |
| `file_outline(path)` | درخت تعریف‌های فایل با شمارهٔ خط | Structure View |
| `find_references(path, line, symbol)` | همهٔ استفاده‌های یک نماد در پروژه | `ReferencesSearch` |
| `go_to_definition(path, line, symbol)` | تعریف نامی که در کد استفاده شده، حتی در کتابخانه یا SDK | `PsiReference.resolve()` |
| `file_relations(path)` | فایل‌هایی که این فایل استفاده می‌کند و فایل‌هایی که از آن استفاده می‌کنند، با تعداد ارجاع | resolve ارجاع‌های فایل و `ReferencesSearch` روی تعریف‌های سطح بالا و عضوهایشان |

- هر پرس‌وجو یک non-blocking read action در smart mode است. تا پایان indexing صبر می‌کند و اگر write action وسطش بیاید، دوباره اجرا می‌شود. دکمهٔ توقف آن را لغو می‌کند.
- نتیجه‌ها فقط از فایل‌های محتوای پروژه می‌آیند و سقف دارند (۶۰ نماد، ۲۰۰ ارجاع، ۶۰ فایل).
- اگر index خطا بدهد، مدل پیام خطا می‌گیرد و با `grep` ادامه می‌دهد.
## graphify (فقط وقتی کاربر روشنش کند)

ایجنت به‌صورت پیش‌فرض از graphify استفاده نمی‌کند. دکمهٔ `◇ graphify` در نوار پایین چت آن را روشن (`◆ graphify`) یا خاموش می‌کند. graphify پلاگین کاملاً جدا از ابزارهای دیگر است:

- graphify در پوشهٔ خود پلاگین نصب می‌شود (`<IDE system>/gapgpt/tools/`). متغیرهای `UV_TOOL_DIR`، `UV_TOOL_BIN_DIR`، `UV_CACHE_DIR` و `UV_PYTHON_INSTALL_DIR` به این پوشه اشاره می‌کنند. پس graphify‌ای که کاربر خودش نصب کرده نه استفاده می‌شود و نه تغییر می‌کند.
- گراف به‌صورت پیش‌فرض در `<IDE system>/gapgpt/graphify/<project hash>/` ساخته می‌شود (`GRAPHIFY_OUT`)، نه در `graphify-out/` پروژه که ممکن است مال ابزار دیگری باشد.
- با گزینهٔ **«ذخیرهٔ گراف در پوشهٔ graphify-out/ پروژه»** در Settings › Tools › GapGPT › گراف کد (`graphInProject`)، گراف در `<project>/graphify-out/` نوشته می‌شود تا از ترمینال هم با `graphify query` قابل استفاده باشد. اگر graphify خودتان یا ابزار دیگری هم از این پوشه استفاده کند، گراف مشترک می‌شود. پلاگین `.gitignore` را تغییر نمی‌دهد؛ اگر لازم است، `graphify-out/` را خودتان اضافه کنید. بعد از تغییر این گزینه، گراف قبلی منتقل نمی‌شود و دفعهٔ بعد که لازم شود در مکان جدید ساخته می‌شود.
- در پروژه هیچ فایلی نوشته نمی‌شود: نه `AGENTS.md`، نه `.git/hooks`. لاگ پرس‌وجوی graphify هم خاموش است.

| دستور / کنترل | کار |
|---|---|
| دکمهٔ `graphify` در نوار ابزار چت (همان گزینهٔ Settings › Code Graph، یعنی `useGraphify`) | روشن: برای هر پیام ابزار `graphify` (`query`، `explain`، `path`) و prompt «از گراف شروع کن» (`GRAPHIFY_ON`) به ایجنت داده می‌شود. خاموش: graphify اصلاً استفاده نمی‌شود. انتخاب ذخیره می‌شود و بین اجراها می‌ماند. |
| روشن کردن بار اول | اگر گراف وجود نداشته باشد، ساخت آن در پس‌زمینه شروع می‌شود. تا آماده شدن، پیام‌ها بدون graphify ارسال می‌شوند و یک اعلان نشان داده می‌شود. |
| به‌روزرسانی خودکار | تا وقتی دکمه روشن است، بعد از پایان نوبتی که حداقل یک `edit_file` یا `write_file` موفق داشته، گراف بی‌صدا (بدون اعلان آماده شدن) به‌روز می‌شود. |
| `/graphify` (یا دکمهٔ «ساخت گراف کد» در Settings) | بار اول graphify با `uv` در پوشهٔ پلاگین نصب می‌شود. بعد گراف ساخته یا به‌روز می‌شود. در پس‌زمینه و بدون LLM انجام می‌شود. |
| `/graphify <سؤال>` | فقط وقتی دکمه روشن است کار می‌کند و prompt `GRAPHIFY_MODE` را برای همان پیام اضافه می‌کند. اگر دکمه خاموش باشد، پیامی می‌گوید دکمهٔ graphify را روشن کنید. ابزار فقط می‌خواند و تأیید لازم ندارد. |

اگر گراف هنوز ساخته نشده باشد، `/graphify <سؤال>` پیام «اول ‎/graphify را بفرستید» را نشان می‌دهد.

## استقلال از ابزارهای دیگر

پلاگین فقط از فضای خودش استفاده می‌کند: `.gapgpt/` در پروژه، `~/.gapgpt/`، پوشهٔ system خود IDE و PasswordSafe. فایل‌های ابزارهای دیگر را نمی‌خواند و تغییر نمی‌دهد. این فایل‌ها شامل `AGENTS.md`، `CLAUDE.md`، `.claude/`، `.cursor/`، `.mcp.json`، `graphify-out/` و `.git/hooks` هستند. prompt ایجنت هم همین را از مدل می‌خواهد. استثناها: گزینهٔ اختیاری «ذخیرهٔ گراف در پوشهٔ graphify-out/ پروژه» (پیش‌فرض خاموش) و دکمهٔ «کپی قوانین و اسکیل‌ها» که فقط با کلیک کاربر اجرا می‌شود، فایل‌های اصلی را فقط می‌خواند و کپی را در `.gapgpt/` می‌گذارد.

## حالت طرح (plan mode)

با کلیک روی چیپ `⏵ agent` در نوار پایین یا <kbd>Shift</kbd>+<kbd>Tab</kbd> روشن می‌شود. در این حالت دستیار فقط ابزارهای خواندنی دارد، طرح را با `exit_plan_mode` نشان می‌دهد و تا تأیید شما چیزی را تغییر نمی‌دهد. با «بله، شروع کن» حالت طرح خاموش می‌شود و همان اجرا پیاده‌سازی را ادامه می‌دهد.

## context و خلاصه‌سازی

بودجهٔ context در تنظیمات (پیش‌فرض ۱۰۰ هزار توکن): در ۶۰٪ خروجی ابزارهای قدیمی حذف و در ۸۰٪ پیام‌های قدیمی با یک درخواست خلاصه می‌شوند. `/compact [تمرکز]` همین الان خلاصه می‌کند.

## ذخیره و ادامهٔ گفتگو

هر گفتگو پس از هر پاسخ در پوشهٔ سیستمی IDE ذخیره می‌شود (نه داخل پروژه): `<IDE system>/gapgpt/sessions/<project hash>/`. با `/resume` یا منوی «⋮ › ادامهٔ یک گفتگو» گفتگوی قبلی با همهٔ پیام‌ها، ابزارها و خلاصه برمی‌گردد. حداکثر ۱۰۰ گفتگو نگه داشته می‌شود.

## MCP

سرورها فقط از فایل‌های خود پلاگین خوانده می‌شوند. قالب فایل همان قالب رایج `mcpServers` است و فایل پروژه سرور هم‌نام را جایگزین می‌کند:

1. `~/.gapgpt/mcp.json`: سرورهای کاربر که بدون پرسش اجرا می‌شوند.
2. `<project>/.gapgpt/mcp.json`

`.mcp.json` ابزارهای دیگر خوانده نمی‌شود تا سرورهای آن‌ها دو بار اجرا نشوند. اگر همان سرور را می‌خواهید، تعریفش را در `.gapgpt/mcp.json` بگذارید.

سرورهای تعریف‌شده در پروژه فقط پس از اجازهٔ شما اجرا می‌شوند؛ اگر تعریف سرور تغییر کند دوباره پرسیده می‌شود.

<div dir="ltr">

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "${HOME}/notes"]
    },
    "remote": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${MY_TOKEN}" }
    },
    "old-one": { "command": "my-server", "disabled": true }
  }
}
```

</div>

- اتصال‌ها: `stdio` (فرایند محلی) و streamable HTTP. انتقال قدیمی SSE پشتیبانی نمی‌شود.
- `${VAR}` و `${VAR:-default}` از محیط shell کاربر جایگزین می‌شوند.
- سرورها با اولین پیام ایجنت اجرا می‌شوند و با تغییر فایل تنظیمات دوباره راه می‌افتند.
- `/mcp` وضعیت سرورها و تعداد ابزارها را نشان می‌دهد؛ `/mcp reload` همه را دوباره اجرا می‌کند و اجازه‌های ردشده را فراموش می‌کند.
- در حالت طرح فقط ابزارهای MCP با `readOnlyHint` در دسترس‌اند.

## دستورهای `/`

| دستور | کار |
|---|---|
| `/clear`، `/new` | گفتگوی جدید |
| `/resume` | ادامهٔ گفتگوی ذخیره‌شده |
| `/compact [تمرکز]` | خلاصه‌سازی گفتگو |
| `/mcp`، `/mcp reload` | وضعیت سرورهای MCP |
| `/usage` | اعتبار حساب، قیمت مدل فعلی و جدول مصرف هر مدل |
| `/usage reset` | پاک کردن شمارنده‌های مصرف محلی |
